How this site is accessible

This page is itself a small accessibility case study. Rather than just list the skill, here's what's actually implemented and why — each item maps to a real WCAG success criterion.

  • Skip-to-content link, visible on keyboard focus — lets keyboard and screen reader users bypass the navigation. WCAG 2.4.1 Bypass Blocks
  • Custom focus outline on every interactive element — never removed without a visible replacement. WCAG 2.4.7 Focus Visible
  • Semantic landmarks (header-equivalent, nav, main) with aria-label so screen reader users can jump between regions. WCAG 1.3.1 Info and Relationships
  • Single logical heading order (h1 → h2 → h3), no skipped levels, so the page outlines cleanly for assistive tech. WCAG 1.3.1 / 2.4.6
  • Decorative icons marked aria-hidden="true"; the text label next to each carries the meaning instead. WCAG 1.1.1 Non-text Content
  • Body text and links meet 4.5:1 contrast against the background; the accent color was checked, not guessed. WCAG 1.4.3 Contrast
  • Mobile menu button uses aria-expanded and aria-controls, and is fully operable by keyboard, not just touch/click. WCAG 2.1.1 Keyboard / 4.1.2
  • Respects prefers-reduced-motion — smooth scroll and transitions turn off for users who've asked for reduced motion at the OS level. WCAG 2.3.3

Tested manually with keyboard-only navigation and VoiceOver. Next: a full axe DevTools + NVDA pass, documented the same way.
